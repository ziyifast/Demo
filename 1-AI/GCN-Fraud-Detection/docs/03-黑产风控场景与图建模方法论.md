# 三、黑产风控场景与图建模方法论

## 3.1 为什么黑产风控需要 GNN

黑灰产呈现出明显的**团伙化、规模化、隐蔽化**特征：

| 攻击类型 | 手段描述 | 传统方法痛点 |
|---------|---------|------------|
| **批量刷单** | 利用大量虚假账号，通过虚假交易刷高商品销量和好评 | 单账号行为看似正常，难以区分 |
| **垃圾注册** | 批量注册虚假账号，用于后续的刷单、刷评论等活动 | 注册信息各不相同，频率限制易绕过 |
| **黄牛囤货** | 在秒杀场景中，利用自动化脚本抢购稀缺商品 | 单个订单行为无明显异常 |
| **刷接口/流量攻击** | 通过分布式代理、模拟器群控等方式高频调用业务接口 | IP 分散在不同地域，黑名单覆盖不全 |
| **虚假评论** | 批量生成虚假好评或恶意差评 | 单条评论内容可能看起来正常 |
| **金融欺诈** | 团伙协同进行欺诈交易、洗钱等 | 单笔交易金额可能低于监控阈值 |

传统风控手段在面对这些团伙化攻击时力不从心：

- **IP 黑名单**：黑产可轻易更换 IP/使用代理
- **频率限制**：黑产可降低单账号频率，通过大量账号分摊
- **单点特征模型**：无法捕捉账号间的关联结构

而 **GNN 能够同时利用节点特征和网络结构**，精准识别隐蔽的团伙欺诈行为。

## 3.2 典型应用场景与行业案例

### （1）批量刷单识别

在电商平台上，欺诈行为包括虚假交易、恶意评价操纵和刷单等，这些行为具有隐蔽性和复杂性——黑产通过构建多层级的间接交易链路规避单账户行为检测。

- MAML-GCN 模型在刷单数据集上进行二分类检测，准确率达到 **89.47%**，精确率达 **91.66%**，F1-Score 达 **90.90%**
- 双通道图神经网络方法通过构建实体交互图和评论语义图，对用户的多维行为建模，能有效识别用户级欺诈行为

### （2）团伙欺诈检测 — 携程酒店案例

在携程酒店场景下，通过构建包含用户账号、设备指纹、IP 地址、支付账号、手机号、邮箱等实体，以及登录、支付、预订等 **7 种以上关系类型**的异构图谱，利用图计算技术挖掘黑灰产团伙。

- 该系统每月可为平台带来**数百万元**的增量止损

### （3）垃圾注册识别 — 阿里巴巴案例

阿里巴巴通过手机号、设备信息、IP 地址等多种关系构建账户之间的连接图，基于 GNN 识别垃圾注册账号。

- 该图模型上线后，相比单纯使用账户特征，每日额外识别 **10%-15%** 的垃圾账号

### （4）虚假评论识别 — 闲鱼/淘系案例

在闲鱼平台，基于异构图卷积网络的反垃圾系统 **GAS**（Graph-based Anti-Spam），能够在同样准确率的情况下获得 **16%** 的覆盖率提升。

在淘系恶意评价场景中，图模型上线后日均额外识别 **7%** 以上的恶意评价。

### （5）金融欺诈检测

将 GNN 应用于交易图谱进行欺诈检测，可以达到 **75.83** 的 AUROC。结合强化学习的框架在召回率上提升了 **19.7%**，误报率降低了 **33%**。

## 3.3 风控图建模方法论

### 五步建模法

```
Step 1: 实体定义   →  确定图中的节点类型
Step 2: 关系抽取   →  确定节点之间的边类型
Step 3: 特征工程   →  为每种节点提取有意义的特征
Step 4: 图构建     →  组装成完整的图数据
Step 5: 模型训练   →  选择适合的 GNN 模型进行训练
```

### Step 1: 实体定义

在风控场景中，常见的节点类型包括：

| 节点类型 | 含义 | 示例 |
|---------|------|------|
| user | 用户账号 | user_12345 |
| device | 设备指纹 | did_abc123 |
| ip | IP 地址 | 192.168.1.1 |
| phone | 手机号 | 138****1234 |
| email | 邮箱地址 | user@example.com |
| payment | 支付账号 | alipay_xxx |
| order | 订单 | order_20230722_001 |

### Step 2: 关系抽取

| 边类型 | 含义 | 关系三元组 |
|--------|------|-----------|
| 登录关系 | 用户使用了某个设备 | (user, logins_on, device) |
| 网络关系 | 用户使用了某个 IP | (user, connects_from, ip) |
| 绑定关系 | 用户绑定了某手机号 | (user, binds, phone) |
| 支付关系 | 用户使用了某支付方式 | (user, pays_with, payment) |
| 交易关系 | 用户之间转账 | (user, transfers_to, user) |
| 共用设备 | 多用户共用一设备 | 推导自登录关系（二度） |
| 共用 IP | 多用户共用一 IP | 推导自网络关系（二度） |

### Step 3: 特征工程

每种节点需要提取有意义的特征：

**用户节点特征示例：**
- 注册天数、活跃度评分、设备更换频率
- 交易金额统计（均值、方差、最大/最小）
- 7 天/30 天登录次数
- 账号等级、是否实名、好友数

**设备节点特征示例：**
- 关联用户数、是否为模拟器
- 设备类型（iOS/Android/Web）
- 使用时长、设备健康度

**IP 节点特征示例：**
- 关联用户数、IP 类型（家庭/企业/机房/代理）
- IP 风险评分、历史黑名单关联度

### Step 4: 图构建

使用本项目的 `src/data/graph_builder.py` 构建：

```python
from src.data.graph_builder import build_heterogeneous_graph

# 定义节点特征
node_features = {
    'user': user_features,      # (N_user, F_user)
    'device': device_features,  # (N_device, F_device)
    'ip': ip_features,          # (N_ip, F_ip)
}

# 定义边
edges = {
    ('user', 'uses', 'device'): user_device_edges,
    ('user', 'from', 'ip'): user_ip_edges,
}

# 构建异构图
data = build_heterogeneous_graph(node_features, edges, labels_dict={'user': labels})
```

### Step 5: 模型训练

```python
from src.models.hetero_gnn import HeteroGNN
from src.train import train_model

model = HeteroGNN(
    node_types=['user', 'device', 'ip'],
    edge_types=[('user', 'uses', 'device'), ('user', 'from', 'ip')],
    target_node_type='user',
    in_channels_dict={'user': 64, 'device': 32, 'ip': 16},
    hidden_channels=64,
    out_channels=2,
)

result = train_model(model, data, device, epochs=200, class_weight=True)
```

## 3.4 风控场景的特殊挑战与对策

### 1. 类别极不平衡

欺诈样本通常占比 **1%-5%**，正常样本占 95%+。

**对策：**
- 使用 Focal Loss（`src/train.py` 中已实现）
- 使用加权 CrossEntropyLoss
- 评估时关注 Precision/Recall 而非 Accuracy
- 使用 PR-AUC 而非 ROC-AUC 作为主指标

### 2. 实时性要求

风控场景需要毫秒级响应。

**对策：**
- 使用图数据库（如 NebulaGraph）存储图结构，支持毫秒级查询
- 预计算节点嵌入，实时只做轻量级的分类推理
- 使用 GraphSAGE 的 inductive 能力进行增量推理

### 3. 持续攻防对抗

黑产手段在不断升级，模型需要快速迭代。

**对策：**
- 建立自动化监控和模型更新 pipeline
- 携程风控通过自动化将模型迭代周期从 30 天缩短到 3 天
- 定期回溯和标注新的欺诈模式

### 4. 可解释性

风控决策需要能够解释"为什么这个用户被拦截"。

**对策：**
- 使用 GAT 的注意力权重分析关键关联
- 使用 GNNExplainer 分析节点预测的关键子图
- 结合规则引擎给出明确的拦截原因
