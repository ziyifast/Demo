# 五、模型部署与上线指南

## 5.1 风控系统总体架构

参考企业级风控系统的设计，整体架构分为三层：

```
┌─────────────────────────────────────────────────────────┐
│                      决策层                              │
│  风险评分 → 处置决策（拦截/验证/放行/人工审核）            │
│  支持实时 + 离线两种模式                                  │
└─────────────────────────────────────────────────────────┘
                          ↑
┌─────────────────────────────────────────────────────────┐
│                      认知层                              │
│  GNN 模型推理 → 节点分类 / 边预测                         │
│  特征实时计算 (Flink/Kafka) + 图嵌入推理 (TorchServe)      │
└─────────────────────────────────────────────────────────┘
                          ↑
┌─────────────────────────────────────────────────────────┐
│                      感知层                              │
│  实时数据接入（用户行为日志、注册、登录、交易）              │
│  图数据库（NebulaGraph）存储 + 实时图更新                  │
└─────────────────────────────────────────────────────────┘
```

### 三层详解

**感知层（数据接入与图构建）**
- 实时接入用户行为日志（登录、浏览、下单、支付、评论等）
- 构建异构关系图谱：节点包括用户账号、设备指纹、IP 地址、支付账号、手机号等
- 边类型包括登录关系、支付关系、预订关系、通讯关系等 7 种以上
- 图数据库需要支持亿级节点、毫秒级查询

**认知层（图神经网络模型）**
- 使用异构图神经网络对多类型节点和边进行建模
- 训练节点分类模型，判断每个账号的欺诈风险
- 使用图嵌入技术生成每个节点的低维向量表示
- 支持在线实时推理 + 离线批量推理

**决策层（风险评分与处置）**
- 综合 GNN 输出的风险分数和规则引擎结果
- 实时输出风险评分，支持毫秒级响应
- 对高风险账号进行拦截、验证或人工审核
- 分级处置：低风险放行、中风险验证、高风险拦截

## 5.3 模型上线流程

### 完整的上线步骤

```
Step 1: 模型训练与评估
  → 在历史数据上训练 GNN 模型
  → 评估效果（ROC-AUC, PR-AUC, Precision@K）
  → 确定最优分类阈值

Step 2: 模型导出
  → 导出 TorchScript 或 ONNX 格式
  → 包含模型权重 + 图结构元信息

Step 3: 模型服务化
  → 使用 Flask/TorchServe 封装推理 API
  → 支持单条推理 + 批量推理
  → 添加健康检查 + 日志 + 监控

Step 4: 灰度发布
  → 先在小流量上验证效果
  → 与现有规则引擎并行运行
  → 对比模型输出与人工标注

Step 5: 全量上线
  → 逐步提升流量占比
  → 建立自动化监控告警
  → 定期回溯模型效果

Step 6: 持续迭代
  → 收集新的标注数据
  → 定期重训模型
  → A/B test 新旧模型
```

### 模型推理服务示例

```python
# deploy/model_server.py
from flask import Flask, request, jsonify
import torch
from src.models.gcn import GCN
from src.data.graph_builder import build_homogeneous_graph

app = Flask(__name__)

# 加载模型
model = GCN(in_channels=64, hidden_channels=128, out_channels=2)
model.load_state_dict(torch.load("saved_models/gcn_fraud.pt"))
model.eval()

@app.route("/predict", methods=["POST"])
def predict():
    """
    接收节点特征和边索引，返回欺诈风险评分。

    请求格式：
    {
        "node_features": [[...], ...],
        "edge_index": [[0, 1, ...], [1, 2, ...]]
    }

    返回格式：
    {
        "fraud_scores": [0.02, 0.95, ...],
        "predictions": [0, 1, ...]
    }
    """
    data = request.json
    x = torch.tensor(data["node_features"], dtype=torch.float)
    edge_index = torch.tensor(data["edge_index"], dtype=torch.long)

    with torch.no_grad():
        out = model(x, edge_index)
        probs = torch.softmax(out, dim=1)
        fraud_scores = probs[:, 1]  # 欺诈类的概率
        preds = out.argmax(dim=1)

    return jsonify({
        "fraud_scores": fraud_scores.tolist(),
        "predictions": preds.tolist(),
    })

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8000)
```

## 5.4 特征实时计算

风控场景需要毫秒级响应，无法在请求时重新计算全图特征。推荐的做法是**离线预计算 + 在线查表**：

```
离线 pipeline:
  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ 历史日志  │ → │ 特征工程  │ → │ 图嵌入   │ → Redis
  └──────────┘    └──────────┘    └──────────┘

在线 pipeline:
  请求 → 查 Redis 获取嵌入 → GNN 分类 → 返回风险评分
  (毫秒级)                      (毫秒级)
```

## 5.5 模型监控指标

上线后需要持续监控以下指标：

| 指标类型 | 具体指标 | 说明 |
|---------|---------|------|
| 效果指标 | Precision/Recall/F1 | 模型预测准确度 |
| 效果指标 | ROC-AUC/PR-AUC | 模型区分能力 |
| 业务指标 | 拦截率/误拦率 | 实际业务影响 |
| 业务指标 | 日止损金额 | 风控业务价值 |
| 性能指标 | P50/P99 延迟 | 推理响应时间 |
| 性能指标 | QPS | 吞吐量 |
| 稳定性 | 模型分数分布漂移 | 检测数据分布变化 |

### 告警规则示例

```
1. 模型 P99 延迟 > 100ms → 立即告警
2. 欺诈预测比例偏离基线 > 30% → 数据异常告警
3. Precision 连续 3 天下降 → 模型退化告警
4. 模型 QPS 超过容器上限 80% → 扩容告警
```

## 5.7 模型迭代

风控是持续的攻防对抗，模型需要快速迭代：

- **自动化监控**：检测模型效果衰减，自动触发重训
- **主动发现**：通过图分析发现新的攻击模式
- **快速标注**：将线上反馈（拦截后的人工审核结果）回流到训练数据
- **A/B Test**：新旧模型并行运行，量化新模型增益
- **目标是**：将模型迭代周期从月级缩短到天级
